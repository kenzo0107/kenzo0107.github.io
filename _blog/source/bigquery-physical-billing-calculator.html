BigQuery 物理ストレージ課金 損益分岐点カルキュレーター

ストレージ課金モデルを LOGICAL から PHYSICAL に切り替えたとき、何%削減できるか（または増えるか）を試算します。

1. 自分のデータの数値を取得する

BigQuery で以下を実行し、対象データセットの行の値をそのまま下のフォームへ入力してください（単位 GiB）。TABLE_STORAGE が未有効の場合は先に有効化が必要です（統計が揃うまで約1日）。

-- 未有効なら先に: ALTER PROJECT `my-project`
--   SET OPTIONS (`region-us.enable_info_schema_storage` = TRUE);

SELECT
  table_schema AS dataset,
  ROUND(SUM(active_logical_bytes)         / POW(1024,3), 3) AS active_logical_gib,
  ROUND(SUM(long_term_logical_bytes)      / POW(1024,3), 3) AS long_term_logical_gib,
  ROUND(SUM(active_physical_bytes)        / POW(1024,3), 3) AS active_physical_gib,
  ROUND(SUM(long_term_physical_bytes)     / POW(1024,3), 3) AS long_term_physical_gib,
  ROUND(SUM(time_travel_physical_bytes)   / POW(1024,3), 3) AS time_travel_gib,
  ROUND(SUM(fail_safe_physical_bytes)     / POW(1024,3), 3) AS fail_safe_gib
FROM `my-project.region-us.INFORMATION_SCHEMA.TABLE_STORAGE`
GROUP BY 1
ORDER BY long_term_logical_gib DESC;

注: active_physical_bytes には time_travel / fail_safe が含まれる定義ではありません。3つは別々に入力してください。

前提と注意

  • 単価は Cloud Billing Catalog API から 2026-09-03 に取得した USD 定価です。値引き契約・通貨・単価改定は反映されません。
  • time travel / fail-safe バイトは Active Physical 単価で計算しています（請求データ上の観測に基づく想定で、単価階層を明記した公式記述は確認できていません）。
  • 毎月10GiBの無料枠、および PHYSICAL では課金されない項目の細部は考慮していません。概算用途に留めてください。
  • 切替後は14日間再変更できません。組織内に同一リージョンのレガシー flat-rate スロットコミットメントがあると登録できません。
